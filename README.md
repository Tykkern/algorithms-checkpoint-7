# Контрольная точка 7: перебор с возвратом, префиксное дерево, битовые операции

Практикум по алгоритмам. Шесть задач, решения на Java.

| № | Задача | Класс | Подход | Время | Память |
|---|---|---|---|---|---|
| 1 | Правильные скобочные последовательности | `Brackets` | перебор с возвратом | O(C(n) · n) | O(C(n) · n) |
| 2 | Количество слов с префиксом | `WordTrie` | префиксное дерево со счётчиками | O(L) на операцию | O(сумма длин) |
| 3 | Два одиночных числа | `TwoSingles` | XOR и разделение по биту | O(n) | O(1) |
| 4 | Ферзи на доске с запретами | `Queens` | перебор с возвратом на битовых масках | экспоненциальное | O(n) |
| 5 | k-е слово с префиксом | `WordTrie` | префиксное дерево, спуск по счётчикам | O(26 · L) на запрос | O(сумма длин) |
| 6 | Максимальный XOR фрагмента | `MaxXorSegment` | префиксные XOR + двоичный бор | O(30 · n) | O(30 · n) |

C(n) это число Каталана (для n = 10 оно равно 16 796), L это длина слова, не больше 50.

## Запуск

Нужен JDK 17 или новее, Gradle скачается сам через wrapper.

```
gradlew test                          # тесты
gradlew run -q --args="2" < input.txt # задача 2, ввод из файла
```

Номер задачи передаётся аргументом, входные данные читаются из stdin в формате
из задания, ответ печатается в stdout. Например, для задачи 5:

```
7
ADD ab
ADD a
ADD abc
KTH a 2
KTH a 4
REMOVE ab
KTH ab 1
```

ответ `ab`, `NONE`, `abc`, каждый в своей строке.

На Windows проект лучше держать в папке без кириллицы в пути. Иначе Gradle
не находит тестовые классы (`ClassNotFoundException`), хотя они скомпилированы.

## 1. Правильные скобочные последовательности

Строка собирается слева направо. Открывающую скобку можно поставить, пока
их меньше n, закрывающую, пока закрытых меньше открытых. Тогда ни в каком
префиксе закрывающих не больше открывающих, и неправильные строки даже не
начинают строиться.

Открывающая пробуется раньше закрывающей, а `(` меньше `)`, поэтому строки
выходят сразу в лексикографическом порядке, сортировать не нужно.

## 2. Количество слов с префиксом

Префиксное дерево (бор). В каждом узле счётчик слов, проходящих через него.
`ADD` идёт по буквам слова, создаёт недостающие узлы и увеличивает счётчики на
пути, `REMOVE` уменьшает их. `COUNT` спускается по префиксу и возвращает счётчик
узла, либо 0, если такого пути нет. Каждая операция O(длина строки).

Узлы хранятся в массивах, а не отдельными объектами. Потомок узла `v` по букве `c`
лежит в `next[v * 26 + c]`. При суммарной длине слов до миллиона узлов тоже может
быть до миллиона, и объекты с массивом из 26 ссылок заняли бы в несколько раз
больше памяти. Массивы растут удвоением.

При удалении узлы не освобождаются, у них только обнуляются счётчики.
Если слово добавят снова, путь уже готов.

## 3. Два числа, которые встречаются по одному разу

XOR всех чисел равен `x ^ y`: парные числа взаимно уничтожаются. `x` и `y`
различны, значит в `x ^ y` есть единичный бит, где они расходятся. Берётся
младший такой бит (`xor & -xor`), и массив делится на две группы по этому биту.
`x` и `y` попадут в разные группы, а оба экземпляра любой пары в одну. XOR одной
группы даёт первое число, второе это `(x ^ y) ^ первое`.

Два прохода по массиву, дополнительная память O(1).

## 4. Ферзи на доске с запрещёнными клетками

Перебор с возвратом по строкам: в каждую строку ставится ровно один ферзь.
Занятые столбцы и обе диагонали хранятся битовыми масками. Свободные клетки
строки получаются одной операцией: `~(столбцы | диагонали | запрещённые)`.
При переходе на строку ниже маска диагоналей «\» сдвигается на 1 в сторону
больших столбцов, маска диагоналей «/» в сторону меньших.

Запрещённые клетки тоже маски, по одной на строку, так что они ничего не стоят
при переборе. Без запретов при n = 14 получается 365 596 расстановок, перебор
занимает доли секунды.

## 5. k-е слово с префиксом

То же префиксное дерево, что в задаче 2, но в узле ещё отмечено, заканчивается ли
в нём слово. Сначала спуск по префиксу. Если слов с ним меньше k, ответ `NONE`.

Дальше спуск к k-му слову. Слово, которое заканчивается в текущем узле, короче
всех слов ниже и поэтому меньше их, оно идёт первым. Потом потомки перебираются
по алфавиту. Если в поддереве буквы меньше k слов, оно пропускается целиком,
а k уменьшается на его счётчик. Иначе спуск в него. На каждом из не больше чем
50 уровней просматривается до 26 букв.

## 6. Максимальный XOR непрерывного фрагмента

XOR фрагмента `a[l..r]` равен `p[r + 1] ^ p[l]`, где `p` это префиксные XOR,
`p[0] = 0`. Ответ это максимум `p[i] ^ p[j]` по всем парам префиксов.

Префиксы складываются в двоичный бор по битам от 29-го к 0-му. Для очередного
префикса идём по бору и на каждом бите стараемся свернуть в противоположную
сторону. Единица в старшем бите стоит больше, чем все младшие биты вместе,
поэтому жадный выбор даёт максимум. Потом префикс сам добавляется в бор.

Узлов не больше `30 · (n + 1) + 1`, около 6 миллионов при n = 200 000, массив
потомков занимает около 48 МБ.

## Решения по неоднозначным местам условия

- Задача 3: два числа печатаются в одной строке через пробел.
- Задача 4: пары запрещённых клеток по условию различны, но повтор пары ничего
  бы не сломал, клетка просто дважды отмечается в маске.
- Задача 5: префикс, которого нет ни в одном слове, даёт `NONE` для любого k.
- Неизвестная операция во входных данных (не `ADD`, `REMOVE`, `COUNT` или `KTH`
  для своей задачи) считается ошибкой ввода.

## Тесты

- на каждую задачу граничные случаи и сверка с переборным решением на случайных
  входах (для словаря сверка с `TreeSet` на случайных последовательностях операций);
- входы максимального размера из ограничений с таймаутом: 16 796 последовательностей
  при n = 10, словарь из 20 000 слов по 50 букв, доска 14 на 14, массивы
  из 200 000 чисел;
- `MainTest` проверяет чтение ввода и формат вывода для всех шести задач.
